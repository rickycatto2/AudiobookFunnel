# Architecture and safety contract

FastAPI serves a local browser UI and a JSON API. A separate single worker claims durable SQLite jobs. SQLite (WAL, busy timeout, transactions) is authoritative; folders never encode queue state. Run exactly one worker; an OS file lock prevents accidental concurrent workers.

Source package → inspected files → proposed book groups → independently reviewed jobs → staged media → verified final book. Root audio and nested audio are both inspected. Folder grouping is a proposal, not permission to merge: every multi-file group starts with grouping review. The review page permits reassignment, exclusion, and explicit ordering. Single files can still contain an anthology; users must review those when metadata is ambiguous. Archives are not extracted in v0.1.

States: REVIEW, READY, PROCESSING, COMPLETE, ERROR. Durable events record transitions. Interrupted PROCESSING jobs return to READY when the exclusive worker restarts. Working files use private per-job directories and are retained. Files are copied, never hardlinked. Source and torrent mounts are read-only. Final publication stages a complete book in a hidden directory on the library filesystem and renames without overwriting an existing destination. A manifest containing job ID and media hash supports recovery after publication but before the database commit. Existing foreign output always produces an error.

Settings persist in SQLite. Paths are container paths within fixed mounts; Windows host mount changes require editing .env and recreating containers. Work, library, source, and torrent roots must not overlap. Integration secrets are stored locally in SQLite, redacted in API responses, and excluded from Git. Protect/back up the config directory. The UI is bound to localhost; remote multi-user access and authentication are outside v0.1. Mutation endpoints require same-origin JSON requests.

AAC input is stream-copied when compatible. Other codecs are converted once to AAC for the chosen M4B output. Mixed encodings are normalized per part before concatenation. Existing chapter boundaries are preserved, otherwise each input becomes a chapter. Final duration and full audio decode are validated before publication. Heavy work starts only within the configured timezone/window unless a job is explicitly overridden; a running encode finishes beyond the window.

Deterministic base scoring: title 35, author 25, narrator 10, duration 15, series 5, series position 5, identifier 5. Exact normalized title and author plus runtime within both 1% and 120 seconds qualifies an Audible candidate for a 95-point floor, explicitly shown as a strong-match adjustment. Missing optional fields do not prevent that rule. Conflicting identifiers, narrator, series/position or language veto automation. Automation also requires verified grouping, enabled auto-approval, the configured threshold and a minimum lead over distinct competing editions. Default automation is off. Fallback print-book sources never auto-approve. Stored review candidates are rescored on read; an explicit auto-match action is required to queue existing review jobs.

DISMISSED is a reversible terminal queue state for job/inspection errors. It preserves the original error, records an event, and prevents rediscovery without touching files. Restore returns to ERROR; it does not queue processing. Status-guarded SQL prevents dismissing active or completed work.

Audible is an unofficial public catalog API and can change or restrict editions. The user's reference is https://github.com/binyaminyblatt/mp3tag-Audible-via-API (behavior/field mapping reference; no source copied). Search by title/author and direct ASIN lookup are supported, including extracting ASIN from Audible URLs. Google Books and Open Library are manual fallback searches. Provider outages leave jobs reviewable with embedded metadata. Each selected/edited field records provenance.

Completed finalization passes create a durable Audiobookshelf scan request. A failed scan retries independently, without re-encoding completed books. Success means the scan request was accepted, not that Audiobookshelf has finished indexing. qBittorrent submission uses its API with an explicit save path. Torrent hashes in SQLite prevent repeat submission; originals remain untouched. Raw imports must already be complete (the existing qBittorrent move-on-completion arrangement).

No automatic cleanup, destructive source changes, archive unpacking, AI scoring, or changes to VPN/movie services. Future work: richer edition matching, resumable encodes, authentication, database migrations beyond initial schema, and audiobook-aware chapter joining.
